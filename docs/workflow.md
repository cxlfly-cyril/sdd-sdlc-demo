# 开发与交付流程

## 需求与规格

建立变更意图，读取当前规格，澄清范围与验收标准。用户审阅规格；在变更意图中记录批准证据后进入实现。

## 方案、实现与验证

维护方案和任务；Agent 根据规格实现并补测试。更新追溯映射，执行项目配置中的检查，把实际结果记入 verification.md。未执行项明确写出。

## PR 与 CI

PR 关联 Issue（如有）、验收编号和验证证据。CI 工作流执行追溯结构检查、类型检查、单元测试、构建与浏览器测试。查看 Acceptance checks 通过后人工审阅合并；当前尚无强制分支保护。

## 演示发布

main 的验收与生产构建浏览器检查通过后，发布 GitHub Pages；部署后验证页面资产并执行线上浏览器验收。线上验收失败将标记工作流失败，但不自动回滚。演示发布以人工合并作为批准，生产环境另行定义审批。

## 可用性监控与维护

Pages monitor 定时检查页面与资产；失败时去重记录事件 Issue，恢复时附证据关闭。运行日志和 monitor-result 保存检测结果。

后续 Agent 诊断并建立新变更：实现缺陷补回归测试，需求变化更新规格。修复通过 PR 审阅，发布后确认恢复。

默认 GITHUB_TOKEN 创建的普通事件通常不会触发另一工作流；采用同一工作流调用处理步骤或显式 workflow_dispatch，验证实际触发链。

## 最终验收

演练一次需求变化和一次隔离环境故障，提供规格版本、测试结果、PR、部署及恢复证据，再声称闭环完成。
